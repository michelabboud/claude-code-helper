## update-check (skill) — Functionally complete and internally consistent (all referenced scripts exist, version matches the remote index), but the frontmatter is missing allowed-tools despite the skill driving Bash/curl/Read/Write, and lacks a canonical `name` field.

- **[HIGH · missing-tools · S] Frontmatter declares no allowed-tools despite shelling out to curl and update scripts** — `skills/update-check/SKILL.md`:1  
  This skill actively drives specific tools: it Reads ~/.claude/claude-code-helper.json (line 26), runs `curl -s https://raw.githubusercontent.com/.../component-versions.json` via Bash (line 59), invokes `bash /path/to/.../scripts/download-component.sh` (line 230) and curl downloads (line 234), and writes/updates the manifest plus backup files (lines 237-241). Yet the frontmatter (lines 2-9) declares NO allowed-tools. Sibling skills that drive tools all declare it: testing (`Read, Write, Edit, Bash, Grep, Glob`), documentation (`Read, Write, Edit, Grep, Glob`), project-scaffolding (`Read, Write, Edit, Bash, Glob`), and rag (explicit MCP list + Bash/Read/Write/Edit). Per the repo convention and the review bar, a skill that shells out to a CLI with no allowed-tools is a missing-tools gap.  
  *Fix:* Add to the frontmatter: `allowed-tools: Read, Write, Edit, Bash` (Read for the manifest, Bash for curl/download-component.sh, Write/Edit for manifest updates and backup pruning).
- **[MEDIUM · consistency · S] No canonical `name` field in frontmatter (only skill_name)** — `skills/update-check/SKILL.md`:2  
  The frontmatter uses `skill_name: update-check` (line 2) but has no `name` field. The review bar for Skills 2.0 requires `name` + description, and sibling skills rag (`name: RAG`) and greeting (`name: greeting`) both carry a `name` field (greeting carries both name and skill_name). The repo's own validate-frontmatter.mjs accepts name|skill_name|command as a fallback, so this passes local validation, but it is inconsistent with the Skills 2.0 canonical field and with the two siblings that already use `name`.  
  *Fix:* Add `name: update-check` to the frontmatter (keep skill_name if desired for backward compatibility, mirroring the greeting skill).
- **[LOW · quality · S] Skill version hardcoded in three places (hello/hello ID) invites drift** — `skills/update-check/SKILL.md`:313  
  The version string `3.0.0` is duplicated literally in the `hello` response (line 313) and twice in the `hello ID` response (lines 317-318: 'update-check v3.0.0'), in addition to the authoritative `version: 3.0.0` in frontmatter (line 4). On the next version bump these hardcoded copies will silently drift out of sync with the frontmatter and the component-versions.json entry (currently all correctly at 3.0.0).  
  *Fix:* Reword the hello/hello ID responses to instruct reading the version from the frontmatter rather than embedding the literal, or add a checklist note in the Changelog section reminding the maintainer to update all three occurrences on each bump.

## project-scaffolding (skill) — Functionally coherent instructional skill with complete allowed-tools; weak (non-trigger-rich) description and several internal doc-consistency gaps.
